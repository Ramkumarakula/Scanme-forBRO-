# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Goal

A free, fully offline Windows desktop tool for the user's brother. He gives it an image, and it checks whether that design already exists in his (already well organized) design folders. It should match even when the colors differ or the design is only nearly the same. For each match it shows the folder, because the **master file sits in the same folder as the matched photo**, and he can jump there in one click. In the end it becomes a small, lightweight window that stays on top of other apps.

`PROJECT_PLAN.md` holds the original handoff. Where it disagrees with the decisions below, the decisions below win. The plan says AutoCAD/`.dwg`, but the user has since said the masters are **SketchUp files (`.skp`) and `.skb` backups**. `README.md` is the user-facing documentation, including a plain-language explanation of how matching works. Keep it current at the end of every phase.

## Confirmed decisions

- Target OS: Windows.
- Master files: `.skp` / `.skb` in the same folder as the matched image.
- Images: `.png`, `.jpg`/`.jpeg` (WhatsApp photos), `.webp` (see `IMAGE_EXTENSIONS` in `__init__.py`).
- Real data from the brother isn't available yet. Develop against the synthetic `mock_data/` (generated by `scripts/make_mock_data.py`). Its `.skp`/`.skb` files are text placeholders. File count and folder locations will come later.
- Done: Phase 1 (PNG index + search CLI), Phase 2 (JPG/WEBP, mock data, eval, README, security checks).

## Stack

Python 3.11, OpenCV + numpy, SQLite (stdlib), pytest, pip-audit + bandit (dev). Later phases (pending user confirmation): Tkinter UI, Pillow `ImageGrab` for capture/clipboard, `watchdog`, PyInstaller.

## Commands

```
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"

pytest                                         # all tests (includes end-to-end mock-data test)
pytest tests/test_search.py::test_recolored_design_matches   # single test

python -m designfinder index <root> [<root> ...]   # build/refresh index (incremental)
python -m designfinder search <image> [--top N]    # list best-matching folders

python scripts/make_mock_data.py               # regenerate mock_data/
python scripts/eval_queries.py [data_dir]      # score queries/expected.csv against designs/

pip-audit --skip-editable                      # dependency vulnerabilities
bandit -q -r src scripts                       # static security scan
```

The index defaults to `data/index.db`; override it with `--db`.

## Architecture

The pipeline runs `scanner` → `fingerprint` → `index` (SQLite) → `search`.

- `fingerprint.py` makes matching color-independent:
  - Converts the image to grayscale.
  - Crops away the plain background **repeatedly**: a screenshot has screen margin, then the image's own background. Then it re-pads uniformly.
  - Applies CLAHE and builds a Canny edge map.
  - For both the edge map and the gray image, keeps a **continuous** 255-value DCT signature: the 16×16 low frequencies minus DC, scaled to unit length.
- `search.py` scores with `(edge·q + |tone·q|) / 2`. The absolute value works because inverting an image negates its tone signature. The **mean** is used, not max: on boxy furniture drawings either signature alone often rates a different design highly. Results are grouped by folder (best score per folder), with the folder's master files attached.
- `index.py` stores the signatures as float32 BLOBs, re-indexes incrementally (mtime + size), and drops deleted files. `PRAGMA user_version` holds `SIGNATURE_VERSION`. **Bump it whenever fingerprint output changes**, and old indexes then rebuild automatically.
- Images are read with `np.fromfile` + `cv2.imdecode`, because `cv2.imread` fails on non-ASCII Windows paths.

Tuning decisions were checked with `scripts/eval_queries.py` on the mock data. Re-run it after any change to fingerprinting or scoring, and keep the README's result table in sync. What was rejected and why:
- Binary pHash: bits flip on near-zero coefficients, and a plain resize scored about 0.65.
- 8×8 signatures with `max` combination: margins were too thin.

The "found / new" threshold has **not** been chosen. It must come from the brother's real example pairs, so the CLI shows ranked scores for now.

## Working rules

- Build one phase at a time, and test each phase (pytest, the eval script, pip-audit, bandit).
- After each phase: update README.md and this file, commit, and **push** (the user asked for a push every phase). There is no remote yet, so ask the user for the repo URL before the first push.
- Never invent content, features, tech choices, or numbers (such as thresholds). Ask the user instead.
- Ask the user for missing assets (sample images, example pairs, folder layouts).
- Never commit `.env`, real sample data (`data/`, `samples/`), the index DB, or other large raw files. `mock_data/` is small synthetic data and is committed on purpose.
- Security: no network calls, no `shell=True`, no `eval`/`pickle`, and parameterized SQL only.

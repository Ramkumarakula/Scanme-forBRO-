# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Goal

A free, fully offline Windows desktop tool for the user's brother. He gives it an image, and it checks whether that design already exists in his (already well organized) design folders. It should match even when the colors differ or the design is only nearly the same. For each match it shows the folder, because the **master file sits in the same folder as the matched photo**, and he can jump there in one click. At rest it is a small draggable floating symbol. Tapping it opens the search window, and it stays lightweight until then.

`PROJECT_PLAN.md` holds the original handoff. Where it disagrees with the decisions below, the decisions below win. The plan says AutoCAD/`.dwg`, but the user has since said the masters are **SketchUp files (`.skp`) and `.skb` backups**. `README.md` is the user-facing documentation, including a plain-language explanation of how matching works. Keep it current at the end of every phase.

## Confirmed decisions

- Target OS: Windows.
- Master files: `.skp` / `.skb` in the same folder as the matched image.
- Images: `.png`, `.jpg`/`.jpeg` (WhatsApp photos), `.webp` (see `IMAGE_EXTENSIONS` in `__init__.py`).
- Real data from the brother isn't available yet. Develop against the synthetic `mock_data/` (generated by `scripts/make_mock_data.py`). Its `.skp`/`.skb` files are text placeholders. File count and folder locations will come later.
- Done: Phase 1 (PNG index + search CLI), Phase 2 (JPG/WEBP, mock data, eval, README, security checks), Phase 3 (Tkinter window, single-file exe, install guide), Phase 4 (floating symbol, in-memory screen capture, Start with Windows, single instance, CI, public-repo hardening).
- Input: **Capture screen** (freeze the screen and drag a frame), Open image…, Ctrl+V (an image or a copied file), or an image path argument ("Open with", only when not already running). Drag-and-drop would need `tkinterdnd2` and hasn't been agreed.
- **Screen captures must never touch disk or the clipboard.** They are kept only in memory and released after the search and on collapse. This is a user requirement.
- The repo is meant to be **public**. Don't commit personal data or screenshots of the user's own screen (crop docs images to app or sample content only). The README presents `mock_data/` as a sample library for trying the tool. The user asked that it not be framed as "just synthetic".

## Stack

Python 3.11, `opencv-python-headless` + numpy, Pillow (capture, clipboard, thumbnails, icon), Tkinter, SQLite (stdlib), PyInstaller. Dev: pytest, pip-audit, bandit. Not done (the symbol replaced them): global hotkey, tray icon, `watchdog`.

Install only the **headless** OpenCV. If you uninstall `opencv-python` alongside it, the shared `cv2` files get deleted, and you need `pip install --force-reinstall --no-deps opencv-python-headless`.

```
python -m designfinder index <root> [<root> ...]   # build/refresh index (incremental)
python -m designfinder search <image> [--top N]    # list best-matching folders

python scripts/make_mock_data.py               # regenerate mock_data/
python scripts/eval_queries.py [data_dir]      # score queries/expected.csv against designs/

pip-audit --skip-editable                      # dependency vulnerabilities
bandit -q -r src scripts packaging             # static security scan (must stay clean)
```

From source, the index defaults to `data/index.db` (override it with `--db`). The frozen exe keeps `settings.json` and `index.db` next to itself, falling back to `%LOCALAPPDATA%\DesignFinder` if that folder isn't writable (`settings.data_dir()`).

## Architecture

The pipeline runs `scanner` → `fingerprint` → `index` (SQLite) → `search`.

- `fingerprint.py` makes matching color-independent:
  - Converts the image to grayscale.
  - Crops away the plain background **repeatedly**: a screenshot has screen margin, then the image's own background. Then it re-pads uniformly.
  - Applies CLAHE and builds a Canny edge map.
  - For both the edge map and the gray image, keeps a **continuous** 255-value DCT signature: the 16×16 low frequencies minus DC, scaled to unit length.
- `search.py` scores with `(edge·q + |tone·q|) / 2`. The absolute value works because inverting an image negates its tone signature. The **mean** is used, not max: on boxy furniture drawings either signature alone often rates a different design highly. Results are grouped by folder (best score per folder), with the folder's master files attached.
- `index.py` stores the signatures as float32 BLOBs, re-indexes incrementally (mtime + size), and drops deleted files. `PRAGMA user_version` holds `SIGNATURE_VERSION`. **Bump it whenever fingerprint output changes**, and old indexes then rebuild automatically.
- Index paths are compared with `os.path.normcase`, because Windows paths are case-insensitive, but the original spelling is kept for display. The app calls `index_roots(present_roots, keep_only=all_roots)`, so a folder removed from Settings is dropped, while an unplugged drive keeps its images. The CLI omits `keep_only`.

UI layering:
- `bubble.py` is the entry point: the Tk root as an `overrideredirect` round symbol. It imports **only tkinter + stdlib** (`settings`, `screen`, `startup`), and `test_symbol_does_not_load_image_libraries` enforces this. `app.py` (OpenCV, numpy, Pillow) is imported on the first tap.
- A tap opens `app.MainWindow` (a Toplevel) beside the symbol and starts a background scan, which also builds the `Index`. Closing or Esc calls `release()`, which drops the query, results and index, and shows the symbol again.
- Worker results come back through a queue that `after()` polls, only while a scan runs, because Tk isn't thread-safe. A search made during a scan waits in `pending_search`.
- `capture.ScreenCapture` hides our windows, grabs the virtual screen with `ImageGrab` (in memory), shows it dimmed in a full-screen borderless Toplevel, and on release hands back only the crop (`finish()` drops the full shot). Per-monitor DPI awareness (`screen.make_dpi_aware`) keeps Tk coordinates equal to screenshot pixels.
- A named mutex keeps it to a single instance. "Start with Windows" uses the HKCU Run key (`startup.py`, frozen exe only), and `repair()` fixes the path if the exe was moved.
- "Open folder" calls `%WINDIR%\explorer.exe /select,"<newest master>"` with no shell. Keep the existence and quote checks in `open_in_explorer`.
- Images are read with `np.fromfile` + `cv2.imdecode`, because `cv2.imread` fails on non-ASCII Windows paths.

Tuning decisions were checked with `scripts/eval_queries.py` on the mock data. Re-run it after any change to fingerprinting or scoring, and keep the README's result table in sync. What was rejected and why:
- Binary pHash: bits flip on near-zero coefficients, and a plain resize scored about 0.65.
- 8×8 signatures with `max` combination: margins were too thin.

The "found / new" threshold has **not** been chosen, and the UI shows ranked scores only. The README's "When can you trust the result?" ranges come from the mock-data eval. Update them if scoring changes, and replace them with real thresholds once the brother's example pairs exist.

## Working rules

- Build one phase at a time, and test each phase (pytest, the eval script, pip-audit, bandit).
- After each phase: update README.md and this file, commit, and **push** (the user asked for a push every phase). There is no remote yet, so ask the user for the repo URL before the first push.
- Never invent content, features, tech choices, or numbers (such as thresholds). Ask the user instead.
- Ask the user for missing assets (sample images, example pairs, folder layouts).
- Never commit `.env`, real sample data (`data/`, `samples/`), the index DB, `settings.json`, built exes, or other large raw files. `mock_data/` is small sample data and is committed on purpose.
- Security: no network calls (no sockets, not even localhost IPC), no `shell=True`, no `eval`/`pickle`, and parameterized SQL only. CI (`.github/workflows/ci.yml`) runs pytest, the eval, bandit and pip-audit on Windows.
